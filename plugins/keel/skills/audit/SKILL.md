# Harness Audit

You are auditing this project's AI engineering infrastructure — the artifacts a
`/keel:setup` session (or an equivalent hand-built harness) laid down. Your job is
to find where the harness has drifted from its own laws, not to fix anything.

**Read-only, enforced and obeyed.** You have no write or edit tools, and Bash is
granted for READING and for running check-mode gates only. Read-only includes git
state: no stash, checkout, restore, reset, or clean, even "temporarily" — compare
against baselines via `git diff` / `git show`, never by mutating the tree. If a
gate's only invocation rewrites files (an in-place formatter with no check flag),
do not run it; record it as not-run instead.

**Scope.** The audit target is the harness itself: `CLAUDE.md`, `.claude/**`,
`docs/`, CI workflows, gate scripts, `.gitignore`. Product code is out of scope
except where running a tier-1 gate requires it.

**Source of truth for required shapes.** The required section order for the
constitution, the required agent-brief headings and frontmatter fields, and the
required checklist items live in this plugin's setup templates — read them from
`../setup/templates/` (`CLAUDE.md`, `agent-brief.md`, `gate-checklist.md`) rather
than trusting this file's summary of them. If the audited harness was generated by
an older keel and predates a template change, say so in the finding rather than
flagging blindly.

Work through the sections below in order. Collect findings as you go; do not stop
at the first one.

## 0. Locate the harness

- No `CLAUDE.md` in the repo root → the harness was never set up. Report that
  single fact, recommend `/keel:setup`, and stop.
- `CLAUDE.md` exists but no `.claude/` directory → either a different harness or a
  partial setup. Audit what exists and list the absent layers as findings.

## 1. The constitution — CLAUDE.md

1. **Required sections present**, in the template's order: competitive axis (one
   bolded sentence), architecture boundary rule, stack table, dev commands, coding
   conventions with the comment ruling, security section naming the radioactive
   material, the numbered Laws, the pre-commit checklist as literal checkboxes,
   Current status.
2. **The live pointer.** Current status must end with the literal
   `**Next free number: …**` line. Cross-check it against `docs/MILESTONES.md`:
   the pointer must be strictly greater than every milestone number already used.
   A collision-in-waiting is a critical finding.
3. **Size budget.** Current status holds at most one short paragraph per milestone
   plus a pointer to MILESTONES.md. Count the lines; if as-built detail has
   accumulated there, name the paragraphs that belong in MILESTONES.md.
4. **Mirrored lines.** Any line that mirrors state living elsewhere must name its
   source of truth. Diff the pre-commit checklist in CLAUDE.md against the one in
   the gate-checklist skill verbatim — any divergence is a finding against
   whichever copy failed to follow its named source.
5. **Leftover scaffolding.** Grep the whole harness for `<placeholder`-style
   angle-bracket stubs and surviving template HTML comments. Anything found is a
   finding — a placeholder in a loaded constitution is a lie every session reads.

## 2. The roster — `.claude/agents/`

6. **Census, discovered not listed.** Glob every agent file. Each must carry the
   frontmatter fields and the brief headings required by
   `../setup/templates/agent-brief.md`. Report per-file, not in aggregate.
7. **Reviewer grants.** Every review agent (`security-reviewer`,
   `adversarial-reviewer`, `design-reviewer`, and anything else whose brief says it
   reviews) must have a tool grant free of write/edit tools, and must carry the
   read-only-includes-git-state clause verbatim. A reviewer with a write grant is a
   critical finding — the constraint exists in prose only, which is how a reviewer
   in the source project stashed away the change set it was reviewing.
8. **Decrees carried (Law 19).** For every entry in CLAUDE.md § Standing decrees,
   verify it appears in the brief of every agent whose job could violate it. A
   decree recorded only in the constitution binds nobody at delegation time.

## 3. Skills and docs

9. **gate-checklist skill** exists, names CLAUDE.md § Agents & gates as its source
   of truth, and its command table's commands actually exist in the repo.
10. **live-verification skill** exists as a real procedure, OR `docs/BACKLOG.md`
    carries its deferral with a trigger. Both missing = the "live proof" checkbox
    in every commit is unfulfillable — critical.
11. **MILESTONES.md honesty.** Spot-check the most recent as-built record: every
    recorded number states where and how it was measured; open items say what was
    NOT run and why. A record with conclusions but no measurements is a finding.
12. **BACKLOG triggers.** Every entry has a why and a trigger. Then check each
    trigger against reality: an entry whose trigger condition has already occurred
    (e.g. "first scaffold commit" in a repo with fifty commits) is an expired
    trigger — the deferral has silently become a permanent hole.

## 4. Verification wiring — run what can be run

13. **Tier-1 gates.** Run each command listed in CLAUDE.md's dev-commands table
    that is safe read-only: lint, typecheck, unit tests, build, the comment-policy
    guard, format in check mode. Report actual output for failures, not summaries.
14. **Vacuity check (Law 8).** Green is not enough: confirm the test runner
    discovered a non-zero number of tests, and confirm each guard has a real
    population (a comment-policy guard scanning zero files passes vacuously — that
    converts "unverified" into "verified"). Do NOT plant violations to RED-prove
    guards — that requires writes; record RED-proof status as not-checked.
15. **CI.** Workflows exist for the code gates and a dependency audit; actions are
    SHA-pinned, not tag-pinned; the audit workflow has a schedule.
16. **Release gate.** The script exists and executes the shipped artifact, or a
    BACKLOG entry defers it with a trigger. Do not run it if it is heavy; record
    it as not-run.
17. **Radioactive material.** `.gitignore` covers the sensitive files named in
    CLAUDE.md's security section. Then check the other direction: grep the
    *tracked* file list for secret-shaped names (`.env`, `*credentials*`, `*.pem`,
    key fixtures). A tracked secret file is the most critical finding this audit
    can produce.

## 5. Report

Produce, in this order:

1. **Ranked findings.** Most severe first. Each finding: severity
   (critical / major / minor) · `file:line` evidence actually read · the law or
   section it violates · a concrete prescription. Prescriptions are proposals for
   the maintainer or a follow-up session — you fix nothing.
   - Critical: protection that is silently absent (reviewer with write grant,
     vacuous or missing guard, tracked secret, unfulfillable checklist item,
     pointer collision).
   - Major: drifted mirror, expired BACKLOG trigger, missing brief section,
     unpinned CI action, failing gate.
   - Minor: size-budget creep, missing measurement in a record, wording drift.
2. **Not checked — open, not waived.** Everything this audit could not run and
   why: RED-proofs (need writes), the release gate if heavy, live verification,
   anything needing a human or a credential.
3. **Scorecard.** One table: each section above → pass / findings count / not
   checked. A harness with zero findings should be rare — say so if you suspect
   your own coverage rather than the harness.
